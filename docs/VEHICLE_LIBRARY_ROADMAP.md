# Vehicle library and fantasy expansion

## Baseline and audit — 28 October 2026

Work continues in the existing app; Floot is paused and is not a dependency. Restore tag `before-vehicle-library-20261028` preserves the previous working application. The previous design refinements remain.

Frontend: React 19, TypeScript, Three.js 0.180, React Three Fiber 9, Drei 10. Existing hash navigation lives in `frontend/src/navigation.ts`, page dispatch in `main.tsx`, shared menus/race context in `SiteShell.tsx`. Existing Engineering Explorer uses `EngineeringShowcase.tsx`, `EngineeringCar.tsx`, `EngineeringDetails.tsx` and installed `GarageAssets.ts` identities. Homepage and driver showcase already reuse those assets. Do not replace these systems.

Backend: FastAPI/OpenF1 historical data, replay contract, careers/Jolpica, news and experimental forecasting remain unchanged. Existing 3D replay uses lightweight procedural cars in `main.tsx`; it does not load showroom GLBs for a complete grid. There is no account database, fantasy scoring, private-league access control or multiplayer persistence yet. Local strategy and garage storage are browser-local only. The existing forecast does not establish calibrated fantasy-points confidence intervals.

Nine installed third-party GLBs: Ferrari 2023 plus eight constructor-labelled 2026 representations. 260k–713k triangles, approximately 18–55 MB each. Exact measured statistics, source hashes and map compatibility are in `vehicleAudit.ts`, regenerated by `tools/audit_vehicle_assets.py`. Every installed inspection map matches the GLB SHA-256. Maps split connected/material surfaces approximately; no genuine internal powertrain or chassis CAD exists. Models are normalised to viewer units, so their bounds cannot establish true vehicle dimensions. No approved race LOD currently exists.

The original procedural `Car` teaching model is a safe display fallback with original geometry, but is not a photorealistic, regulation-certified 2026 vehicle. Replacing it with a high-quality original engineered asset remains work, not a completed claim.

## Implemented first viable stage

- `VehicleAssets.ts`: provider-neutral registry, provenance, SHA version, creator/source/licence, attribution, restrictions, download/modification permissions and explicit commercial/race eligibility gates. Commercial review is false for every current model. Those gates must be enforced server-side before future paid or multiplayer asset-serving features; this client registry is not an authorization system.
- `VehicleLibrary.tsx`: ten-vehicle searchable catalogue (nine installed + original study), season/constructor/size/engineering filters, favourites and personal-garage display selection, side-by-side comparison with matching camera presets and fact/estimate limitations.
- `VehicleViewer.tsx`: same installed EngineeringCar geometry, orbit/zoom/camera presets, component highlighting, reversible separation, material transparency study, labelled illustrative animated flow, fullscreen, reduced-motion handling, failure/loading states and optional official Sketchfab embeds.
- `EngineeringCar.tsx`: transparency uses cloned materials, preserves authored opacity, and restores exterior materials. It does not invent missing internals. Existing viewer behaviour remains default.
- `navigation.ts`, `SiteShell.tsx`, `main.tsx`: Vehicle library and My personal garage integrated into Drivers & Cars.
- `vehicleAssets.test.mjs`: provenance, permission gates, corrupt-storage restoration and safe embed URL validation. Existing simulator gates remain required.

Appearance selections never mutate performance or scoring. No new third-party downloads, scraping, authentication flows, subscriptions or payments were introduced. The registry currently derives installed permissions from existing creator metadata; future intake must retain download-time licence evidence and review it before importing any new asset.

## Research and integration boundaries

Official documentation checked on 28 October 2026:

- https://sketchfab.com/developers/data-api/v3 — public metadata/search API; some endpoints require auth.
- https://sketchfab.com/developers/download-api and /guidelines — end users must authenticate through Sketchfab OAuth to download. Attribution and licence must follow assets throughout reuse. No unattended download bypass.
- https://sketchfab.com/developers/viewer and /functions — embedded viewer controls operate within Sketchfab's permitted viewer; they do not grant reusable mesh bytes.
- https://sketchfab.com/developers/oembed — official embed endpoint; model links can be embedded. This stage constructs canonical embeds only for installed registry sources and loads them on request.
- https://sketchfab.com/licenses and https://sketchfab.com/developers/terms — licence-specific restrictions apply; editorial does not permit commercial promotion; creator permission does not automatically clear third-party marks or likeness rights.

The tag page returned 403 to research fetch. No scraping workaround was used. A Discover link opens it normally. Live API search, OAuth downloads and model import are deliberately a later intake stage, not simulated catalogue results. Embeds can be unavailable if creators/platform restrictions change; the original source link remains available.

## Incremental implementation plan

1. **Current stage: audited catalogue / viewer / saved garage.** Complete existing gate checks and desktop/mobile interaction checks. Use the exact original model across Engineering and catalogue.
2. **Engineering accuracy and intake.** Define a versioned asset manifest schema with retained licence evidence; add validated model intake through Sketchfab OAuth and other authorized providers; inspect glTF transforms, bounds, texture dimensions, animation and separate geometry. Build a higher-quality original 2026-inspired default. Add verified dimensional facts with cited source/date. Only real authored internal meshes unlock internal X-ray layers; maintain current transparency study separately. Add smooth mode transitions and measured device budgets.
3. **Race assets.** Produce reproducible, licence-permitted decimation/texture compression and distinct showroom/engineering/race paths with retained attribution, source hashes and visual QA. Benchmark a full instanced grid before setting racePath and enabling registry race eligibility. Preserve current procedural race renderer until then.
4. **Fantasy persistence and team builder.** Add server-side PostgreSQL models/migrations for accounts, immutable ruleset versions, season fixtures, rosters, budgets and deadlines. Define original configurable scoring and roster rules; no copying official F1 Fantasy mechanics. Implement validated team CRUD and saved lineup snapshots before visible rankings.
5. **Verified results and scoring.** Import and deduplicate actual qualifying/race/sprint results, record provenance and verification state, implement deterministic scoring and administrator corrections/audit trail. Never award provisional or unverified points. Test historical-season rules including fastest-lap applicability.
6. **Season management.** Transfers, deadline enforcement, budgets/prices, standings/reports, private-league membership checks, global rankings, onboarding and separately labelled archive/off-season leagues. Use server authorization for every private competition read/write.
7. **Fantasy predictions.** Adapt existing forecast into a calibrated model with actual finishing distributions, retirement probabilities, expected scoring and held-out historical accuracy. Assistant explanations must cite calculated inputs; no invented confidence or fantasy projections.
8. **AI season and 3D simulations.** Seeded, saved simulation fixtures, different opponent policies, reproducible outcomes and commentary; distinct data-source labels and tables from actual-result competitions. Connect optimized approved appearances without changing scoring.
9. **Strategy competitions and readiness.** Reproducible shared scenarios, server-verified scores, private/public rankings, performance measurements, account/security and rights review. Feature flags may separate potential premium capabilities, but payments remain disabled. No wagering or cash-prize system.

Acceptance: preserve recorded replay/source labels, strategy engine, selectors, missing-model HTML rejection, driver profiles/carousel and source credits. Keep the full test gate passing at each stage. Explicitly report incomplete roadmap work rather than presenting a future feature as functional.
